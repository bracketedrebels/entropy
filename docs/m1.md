# M1: HTTP → граф → HTTP

## Принятые границы

Entropy не зависит от Trinet. Компилятор написан на MoonBit; целевая программа —
JS-модуль для Node.js. RxJS отвечает за Observable, подписку, завершение,
переключение и teardown. HTTP-адаптер владеет ресурсами платформы: сокетами,
таймерами ответа и таблицей незавершённых запросов.

Модуль объединяет элементы. `native` задаёт внешний контракт и binding для
backend; `graph` задаёт композицию. Модуль может содержать оба вида. Для
публичных истоков и стоков используем существительные, для функций — глаголы.

В `graph` запрещены аннотации типов, лямбды и произвольный JS. Несколько входов
разрешены, выход ровно один. `graph function` — сериализованный подграф
композиции, а не тело функции на пользовательском текстовом языке. Замыкания
возникают в backend при частичном применении.

## Формат M1

```lisp
(module example
  (graph function pair (inputs left right)
    (output (tuple (left left) (right right))))

  (graph function withName (inputs)
    (output (partial pair "Dan"))))
```

`withName` возвращает функцию, у которой правый аргумент остаётся generic.
Аннотации в этом примере отсутствуют. Числа на уровне типов отложены.

| Форма | Значение |
| --- | --- |
| `(node name expression)` | Узел; ссылки задают рёбра, порядок записи не задаёт порядок выполнения |
| `(output expression)` | Единственный выход подграфа |
| `(call function args...)` | Полное применение или вызов подграфа |
| `(partial function args...)` | Связывание начальных аргументов с сохранением оставшихся generics |
| `(tuple (field expression)...)` | Именованный кортеж, тип выводится по значениям |
| `(field value name)` | Проекция с выводом ограничения на строку полей |
| `(vector values...)` | Однородная последовательность без длины в типе |
| `"text"`, `true`, `false`, `unit` | Значения конфигурации/аргументов; Unit — единственное пустое значение |
| `(call std.constant value)` | Исток-константа: один `next(value)` и `complete` на подписку |
| `(schema name "file.json")` | Известная при компиляции схема из config space |

Литерал в параметре узла не создаёт отдельную подписку. Когда константа нужна
как самостоятельный исток графа, её представляет `std.constant` (`RxJS.of`).
Это граница сериализации M1; редактор сможет создавать такие узлы автоматически.

Все элементы модуля экспортируются под `module.name`. Имя без префикса сначала
ищется среди локальных входов/узлов, затем в текущем модуле. Графы могут ссылаться
на объявленные ниже графы. Циклы узлов и рекурсивные подграфы пока запрещены.
Неиспользованные узлы тоже проверяются и вычисляются: нельзя скрыть ошибку или
явно подключённый сток, не соединив его с выходом.

## Вывод типов

Алгоритм использует унификацию с occurs check, инстанцирование схем типов на
каждой ссылке на элемент и обобщение на границе подграфа. Внутри одного вызова
узел мономорфен; многократные вызовы подграфа получают независимые переменные.
Это ограниченный HM-подобный вывод, не обещание поддержки всех полиморфных
программ. Нет higher-rank polymorphism, рекурсии и polymorphic let внутри графа.

Кортежи структурные: открытый хвост позволяет выводить зависимости между
полями и принимать дополнительные поля. В JS значения хранятся в замороженном
массиве с дескриптором имён. Проекция пока ищет индекс по дескриптору. Полное
стирание имён потребует специализации/передачи layout и оставлено следующему
backend-проходу. На HTTP-границе кодек переводит JSON-объект в кортеж и обратно.

Нативные авторы объявляют opaque-конструкторы через `(native-type Name (a ...))`
и сигнатуры через `(forall (a ...) (fn (Input ...) Output))`. `Stream`, `Result`,
`Schema`, `Request` и HTTP-типы объявлены в модулях. Примитивы `Unit`, `Bool`,
`String`, `Int32`, `Int64`, `Float32`, `Float64` и `Vector` известны ядру.
Числовых литералов и операций в M1 ещё нет: наличие имени типа не фиксирует
политику overflow, NaN, Infinity или представление Int64 на разных платформах.

`std.encode` несёт неявное ограничение `JsonEncodable`. Оно переносится через
generic-подграфы и отклоняет функции, Stream, opaque-типы и неподдерживаемые
числовые преобразования до запуска. В M1 допустимы String, Bool, Int32, JSON,
векторы и закрытые кортежи из допустимых значений. Неопределённое ограничение
в точке входа — ошибка.

`source` возвращает `Stream a`, `sink` — `Unit`. Обычная функция не вызывает
истоки/стоки; callback операторов может быть только чистой функцией. Исток нельзя
передать как callback. Общая система эффектов и композиция фабрик ресурсов
для switchMap потребуют отдельного дизайна; M1 не выдаёт эту проверку ролей за
завершённую систему эффектов.

## Схема как первоисточник

`person.schema.json` описывает вход запроса. Компилятор получает из неё тип
`(tuple (first String) (last String))`. `std.validate` имеет полиморфную
сигнатуру `Schema a × JSON → Result ValidationErrors a`; известная схема
специализирует `a`. Пример обрабатывает результат через `std.fold`.

M1 принимает только Draft 7 со строками и объектами, в которых все поля
обязательны и `additionalProperties: false`. Допустимы вложенные объекты,
`title` и `description`. Любые другие ключевые слова, включая `$ref`, `oneOf`,
`minLength`, boolean-схемы и числовые типы, отклоняются. Уточнения будут добавляться
вместе с тестами согласованности типов и runtime-валидации.

Runtime использует AJV без coercion, defaults и удаления полей. Отсутствующие,
лишние или повторяющиеся query-параметры не превращаются в допустимые данные.
Повторяющийся параметр представлен массивом и не проходит String-схему.

## HTTP и эффекты

`http.requests` — один разделяемый Observable на конфигурацию endpoint.
`fullname.requests` — Entropy-композиция этого истока с `http.readQuery`.
`fullname.responses` — Entropy-обёртка над нативным стоком.

Каждый запрос получает opaque capability, хранящуюся внутри `Request a`.
`http.getPayload` возвращает данные; `http.makeResponse` переносит capability
в `Response` вместе с чистым описанием `Reply`. `Request` и `Response` имеют
разные типы. Сокет доступен только окружению стока.

`formatName` использует проекции, `std.join` и конструктор кортежа. В нативном
runtime нет функции склейки имени или другой бизнес-логики примера.
`prepareResponse` превращает успешную валидацию в 200, ошибку — в 400. Ошибка
валидации является значением Result и не завершает общий поток запросов.

Первый ответ на capability выигрывает; последующие игнорируются. Истёкший
запрос получает 504; отключение клиента удаляет его из таблицы. При остановке
runtime снимает подписки, завершает ожидающие запросы и закрывает соединения.
Неожиданная ошибка нативного оператора завершает приложение с 500 для ожидающих
запросов; она отличается от штатной ошибки валидации.

Host конфигурируется через `project.json.config` и может быть переопределён
аргументом `createProgram(config)`. В M1 это один GET endpoint на приложение.
Путь `/full-name` задан только примером. Сервер по умолчанию слушает localhost.

## Backend и будущие границы пакетов

Проходы: s-expression с позициями → определения модулей → типизированные
узлы → JS. CLI принимает JSON bundle и возвращает JS плюс карту сигнатур.
Нативный binding разрешается статическим реестром MoonBit в `nodejs.mbt`:
генератор выдаёт JS-выражение, которое подключает реализацию runtime.
Конфигурация попадает в сгенерированный host. Runtime-пэйлоад запросов никогда
не передаётся MoonBit-компилятору.

В M1 runtime поставляется рядом с приложением и импортируется относительным
путём; зависимости зафиксированы в package-lock. При выделении пакетов эта
связь станет версионированным импортом. Ядро `compiler`, JS runtime и модульные
контракты уже разделены каталогами. Ни один из них не импортирует Trinet.
Динамические backend-плагины, npm/crates публикация, semver контрактов и
deployment-агрегатор относятся к следующим этапам.

## Критерии приёмки

- Native MoonBit-компилятор генерирует запускаемый JS из файлов примера.
- Тесты того же ядра проходят на Wasm GC.
- GET с Dan/Mironenko возвращает точный ожидаемый JSON.
- Невалидный запрос получает 400; следующий запрос работает.
- Параллельные и запоздалые ответы не смешиваются; повтор не пишет в сокет.
- Disconnect, timeout, bind failure и stop освобождают ресурсы.
- Несовместимые типы, циклы, неизвестные поля, недопустимая сериализация,
  неподдерживаемые схемы и пользовательские аннотации отклоняются компилятором.
- Generic-зависимости между входами и частичное применение выводятся без аннотаций.

HTTP пример и core-тесты — регрессионная граница для следующей итерации.
