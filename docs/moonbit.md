# MoonBit в этом репозитории

Основная точка входа — `compiler.compile(bundle: Json) -> Json raise`.
Компилятор не читает файлы, не открывает сокеты и не вызывает JavaScript.
Поэтому его тесты исполняются как native и Wasm GC без замены алгоритмов.

`enum` описывает варианты данных: например, `Type` — переменная, применение
конструктора, функция или строка полей. `match` разбирает варианты; компилятор
MoonBit проверяет полноту сопоставления. Это удобнее цепочек проверок тегов.

`struct` объединяет поля. Поля без `mut` нельзя переназначать, но массивы и Map
сами являются изменяемыми коллекциями. Так `Inference.substitutions` хранит
решения переменных типов, а `mut next` выдаёт свежие идентификаторы. Эти
изменения — детали работы компилятора, не эффекты пользовательского графа.

`raise` в сигнатуре объявляет возможность ошибки. `CompileError` — отдельный
вид ошибки с текстом и позицией в исходном графе. CLI перехватывает ошибки,
печатает структурированный JSON и завершает процесс с ненулевым кодом.

`guard value is Pattern else { ... }` проверяет форму значения и после проверки
предоставляет связанные с паттерном переменные. `Some`/`None` используются
вместо null; обращения к Map возвращают Option.

Запись `fn Inference::unify(self: Inference, ...)` — метод, вызываемый как
`inference.unify(...)`. Методы здесь группируют операции над состоянием вывода.

`Array[Type]` и `Map[String, Definition]` — обычные generics MoonBit. Они
независимы от generic-параметров Entropy, которые мы моделируем через `Var(Int)`.
Строки с `\{expression}` интерполируются MoonBit. В JS backend это используется
только после проверки графа; пользовательские строковые литералы экранируются
JSON-сериализатором, а локальные идентификаторы генерируются компилятором.

`compiler_wbtest.mbt` — white-box тесты: они видят закрытые функции пакета.
Так можно проверять унификацию и ошибки без экспорта внутреннего API. `moon fmt`
добавляет разделители `///|` и форматирует определения; они не меняют семантику.

`cmd/entropy/main.mbt` — тонкий native CLI. Node-скрипт собирает файлы проекта в
JSON bundle и запускает его как отдельный процесс. Это временный файловый host:
передача bundle через argv ограничена лимитом аргументов ОС. Для больших
проектов понадобится stdin или самостоятельный MoonBit file host. Само ядро
для этого менять не нужно.
