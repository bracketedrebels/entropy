# Визуализатор графов

[Открыть GitHub Pages](https://bracketedrebels.github.io/entropy/).

Это статический просмотр проверенного графа, без редактирования и исполнения
HTTP-программы. Структура страницы вдохновлена
[FlowTune от Jack R. / RonDesignLab](https://dribbble.com/shots/25813944-FlowTune-Dashboard-Optimizing-Flow-Processes):
тёмный фон, точечная сетка, цветные узлы и спокойная панель инструментов.
Разметка, иконки и стили реализованы здесь самостоятельно.

## Откуда берутся данные

`compile(bundle, backend)` возвращает `visualization` вместе с JavaScript и сигнатурами.
Экспорт версии 1 содержит `entry`, `graphs`, `elements`, `signatures`, `sources`.
Он строится в `compiler/visualization.mbt` после проверки типов по тому же Typed
IR, который использует JS backend. Браузер ничего не парсит и не выводит типы.

| Поле | Назначение |
| --- | --- |
| `elements` | Каталог графов, нативных элементов и схем, их роли и позиции в исходниках |
| `graphs[].nodes` | Входы, вызовы, частичное применение, значения, проекции, кортежи и единственный выход |
| `nodes[].inputs` | Упорядоченные входные порты с выведенными типами |
| `graphs[].edges` | Связь `from → to`, индекс входа `port`, тип значения и вид связи |
| `signatures` | Обобщённые сигнатуры элементов, включая требования JsonEncodable |
| `sources` | Исходники модулей для вкладки Source |

Локальная ссылка повторно использует существующий узел: два ребра от `person`
не означают два вычисления. Простые псевдонимы не создают дополнительных
вычислительных узлов. Function value и schema/configuration показаны отдельными
видами рёбер. Статическая схема — не событие; граф не изображает расписание RxJS.

В панели деталей тип узла в текущем графе отделён от общей сигнатуры элемента.
Например, вызов `prepareSuccess` получает конкретный закрытый кортеж после
валидации, а его самостоятельный граф сохраняет полиморфный хвост полей.

## Навигация

- Слева: каталог смешанных модулей и поиск по имени, роли или виду элемента.
- Нажатие на узел: тип, входы, сигнатура, значение или JSON Schema.
- Open subgraph или двойное нажатие: переход к устройству Entropy-элемента.
- Graph / Source: граф или исходный модуль с подсветкой определения.
- Перетаскивание фона и колесо: камера. Ctrl/Meta + колесо и `+`/`−`: масштаб.
- Fit или `0`: весь граф. `/`: поиск. Escape: закрыть панель/каталог.
- Copy graph link: ссылка с выбранным графом и узлом; работают Back/Forward.

Узлы нельзя перемещать, соединять, удалять или изменять. На узком экране
начальный масштаб сохраняет читаемость, весь граф доступен через Fit и камеру.
Количество узлов и элементов реально; показателей выполнения здесь нет.

## Сборка и публикация

```sh
npm ci
npm run build:pages
npm run dev
# http://localhost:5173/ или http://localhost:5173/entropy/
```

Для другого проекта: `node scripts/build-pages.mjs path/to/project.json`
после сборки компилятора. `name` в manifest задаёт заголовок. Результат `_site/`
содержит только viewer и JSON-экспорт; RxJS, сервер и исполняемая программа туда
не входят. Относительные пути работают под GitHub Pages project path.

`npm test` собирает и проверяет экспорт, структуру, типы, layout и Pages artifact.
CI сохраняет artifact на PR и публикует его только из master после проверок.
Для workflow с `deploy-pages` выбрать Settings → Pages → Source → GitHub Actions.
Первое демо можно разместить в существующей ветке gh-pages без слияния PR.

Исходные ссылки сборки CI указывают на точный `GITHUB_SHA`. Локальная сборка
с изменениями помечается Local build и ссылается на рабочую ветку.
