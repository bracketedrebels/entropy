# Выбор s-expression парсера

Для текущего этапа проверен опубликованный
[`sennenki/sexp` версии 0.1.1](https://mooncakes.io/docs/sennenki/sexp@0.1.1)
и исходники его [архива](https://download.mooncakes.io/user/sennenki/sexp/0.1.1.zip).
Пакет пока не добавлен как зависимость.

Его публичные `parse` и `parse_many` возвращают Sexp с вариантами Symbol, String,
List и несколькими видами литералов. Но отдельные узлы Sexp не содержат позиции
в исходном тексте. Position принадлежит закрытому Lexer. SexpPath указывает путь
в структуре при декодировании, а не строку и столбец исходника.

Entropy сохраняет позицию каждого выражения: позже она используется в ошибках
типов, неизвестных имён, недопустимых ролей и при переходе из визуализатора к
определению. Замена на этот API потребовала бы второго прохода с разбором текста
для восстановления позиций либо изменения самого пакета. Поэтому сохраняем
небольшой `compiler/sexpr.mbt` до появления подходящего API с позициями.

Также диалект библиотеки включает числовые и символьные литералы, `#t`/`#f` и
`#;`-комментарии. Их поддержку нельзя автоматически считать частью Entropy:
синтаксис и семантика литералов должны быть согласованы отдельно. В M1 строки
декодируются как JSON, а `true`, `false`, `unit` обрабатывает семантический проход.

Условия для повторного рассмотрения готового парсера:

- позиции или диапазоны каждого атома и списка доступны через публичный API;
- можно сохранить текущую грамматику и строгое декодирование строк;
- некорректный и слишком глубоко вложенный ввод обрабатывается предсказуемо;
- те же проверки проходят на native и Wasm GC.

Это решение относится к проверенной версии, а не ко всем будущим версиям пакета.
