# Организация модулей

Модуль — единица организации исходников. Его декларации, runtime, генераторы,
манифесты, README и собственные тесты размещаются в `modules/<name>/`.
Внутренние ссылки — относительно этой папки; межмодульные зависимости объявляются
через публичные манифесты. Отдельного общего каталога `runtime/` нет.

`package.json` одновременно описывает npm-пакет и секцию `entropy`:

```json
{
  "name": "@entropy/example",
  "private": true,
  "type": "module",
  "entropy": {
    "namespace": "example",
    "source": "./module.ent",
    "dependencies": ["../stdlib/package.json"],
    "platforms": {
      "nodejs": { "generator": "example", "runtime": "./runtime.mjs" }
    }
  }
}
```

Внутри `entropy` пути `source`, `dependencies` и `runtime` отсчитываются от самого
манифеста, не от проекта и не от cwd. `namespace` идентифицирует подключение и
должен совпадать с именем в `(module ...)`. Секция `platforms` не нужна модулю,
состоящему только из Entropy-графов. `.ent` можно подключать напрямую для таких
исходников, как пользовательская программа в примере.

Загрузчик выполняет обход зависимостей, устраняет повторные подключения по
каноническому пути и отклоняет циклы, конфликтующие namespace и отсутствующие
файлы. Пути JS-импортов вычисляются от конкретного выходного файла. Тест переноса
копирует весь stdlib в другую папку и запускает результат без HTTP.

`catalog.mbt` и `moon.pkg` — точка статической линковки поставляемого CLI.
Они выбирают только явно подключённые генераторы. Это единственное место, где
перечислены реализации генераторов: вся логика находится в `stdlib/nodejs.mbt`
и `http/nodejs.mbt`. Для добавления/удаления встроенного модуля нужно изменить
его импорт и регистрацию в каталоге, а также зависимости использующих его
проектов. Никакие части реализации не нужно искать в компиляторе.

Ядро принимает `compile(bundle, backend)` и зависит только от общего контракта
`backend/nodejs`. Внешний host может собрать этот контракт из собственных
MoonBit-генераторов, не меняя код ядра. M1 не обещает динамическую загрузку
MoonBit-плагинов или автоматическую установку модулей из registry.

Корневой npm workspace связывает локальные пакеты и хранит единый lockfile.
JS-зависимости объявляются у владельцев. При выделении отдельного репозитория
пакет получает собственный lockfile и подключает опубликованный контракт backend.
