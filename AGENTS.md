# Правила работы над Entropy

## Назначение и границы

- Entropy — самостоятельный Pure Tacit FRP язык. Trinet — первый потребитель,
  а не часть семантики языка. Не встраивать Job, assignee, CQRS и прочие сущности
  Trinet в компилятор, базовые типы или стандартную библиотеку.
- Учитывать будущие платформы и продукты, включая ECS, но не реализовывать их
  заранее. Сейчас компилятор — MoonBit, цель пользовательской программы — JS.
- Границы compiler / runtime / modules / examples / viewer должны позволять
  вынести компоненты в отдельные репозитории. Не вводить скрытые зависимости
  на окружение одного продукта.

## Семантика языка

- Нативность — свойство элемента, а не модуля. Один модуль может экспортировать
  нативные элементы и Entropy-графы. Базовые функции тоже нативные.
- Истоки и стоки называются существительными (`requests`, `responses`),
  преобразования — глаголами (`readQuery`, `formatName`).
- Пользовательский граф имеет ровно один выход и может иметь несколько входов.
  Входные порты соответствуют аргументам. Generic-зависимости между ними
  выводятся из структуры графа и сохраняются при композиции.
- В user space **нельзя** объявлять типы, сигнатуры, generics или произвольные
  lambda/host-функции. Типы строгие, статические и выводимые; явные сигнатуры
  допустимы у нативных элементов. Литеральные и зависимые типы отложены.
- Чистые функции возвращают значения, включая описания эффектов. Эффекты
  исполняет окружение через стоки. Описание эффекта не равно его исполнению.
- Reactive Extensions — runtime языка. Экземпляр истока — Observable.
  Жизненный цикл, подписки и отмена делегируются RxJS в JS backend. Не писать
  параллельный scheduler. Stream и операторы (`map`, `switchMap`) входят в stdlib.
- Константа-исток — одноразовое событие. Литералы в аргументах M1 являются
  статическими значениями; явный `std.of` поднимает значение в поток.
- Configuration space подключает и настраивает элементы. Конфигурация backend
  не должна зависеть от будущего runtime payload.

## Типы, данные и переносимость

- JSON Schema Draft 7 — источник типа проверяемого JSON. Не генерировать
  валидатор по одной лишь сигнатуре. Неподдерживаемые ключевые слова отклонять
  явно; не принимать их с более слабой проверкой. Не включать coercion.
- Невалидные данные — явный Result. Ошибка одного HTTP-запроса не должна
  завершать общий поток. Request и Response — разные сущности с сохранённой
  корреляцией; не подменять Response типом Request.
- Именованные кортежи отделять от платформенного представления. Не полагаться
  на случайный порядок полей JS-объекта; использовать согласованный layout.
- Unit содержит единственное значение; это не unknown. Не переносить числовые
  особенности JS на все платформы. Общая числовая семантика ещё не определена.
- Ядро MoonBit не зависит от файловой системы, сети, JS FFI или HTTP runtime.
  Ввод/вывод — в CLI/host; JS генерируют платформенные генераторы. Не писать
  пользовательский целевой код на MoonBit.

## Визуализатор

- Эта итерация — только чтение. Разрешены навигация, выбор элемента, поиск,
  масштабирование и перемещение камеры; редактирование графа не входит в задачу.
- Структура и типы берутся из проверенного IR компилятора. Не создавать второй
  parser/typechecker в браузере и не рисовать вручную копию HTTP-примера.
- Отделять общую сигнатуру элемента от типа конкретного применения. Не выдавать
  статическую структуру за runtime telemetry или результаты выполнения HTTP.
- Ассеты Pages должны работать под `/entropy/`, а не только в корне домена.
  Не включать исполняемый сервер, секреты или зависимости Node.js в Pages.

## Работа с кодом и проверка

- Документация проекта и пояснения непривычных приёмов MoonBit — на русском.
  Комментировать причины решения и ограничения, а не пересказывать код.
- Ошибки должны быть содержательными и типизированными там, где это возможно.
  Если появится TypeScript, предпочитать readonly входы и `import type`.
- Обновлять существующий PR текущей задачи; не сливать PR автоматически.
  При продолжении проверять рабочее дерево и актуальную удалённую ветку.
  Не перезаписывать чужие изменения; использовать expected SHA при обновлении.
- Перед завершением: `npm test`, `npm run test:wasm`,
  `moon check --target native --deny-warn`, `moon fmt --check`, `git diff --check`.
  Для viewer проверить desktop, узкий экран и путь проекта `/entropy/`.
- Тестировать существенное поведение: структуру экспорта, типы, разделяемые
  значения, ошибки layout и реальный HTTP. Не добавлять тесты ради покрытия
  тривиальной разметки. Держать README, lockfile и CI согласованными.
- Сборка PR готовит Pages artifact. Автоматическая публикация — из master после
  успешных проверок; PR не должен публиковаться как production автоматически.
  Разовая публикация демо из этой ветки отдельно запрошена пользователем.
- Завершать уже разрешённую работу без повторного запроса подтверждения.
  Сообщать о реальных ограничениях проверки и не объявлять успех до проверки.
